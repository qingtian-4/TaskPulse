# Prepare a TaskPulse Alpha release

Read AGENTS.md and docs/RELEASING.md first. This command is not blanket permission
to push, tag, merge or publish.

1. Verify the requested version and scope. Alpha tags use vMAJOR.MINOR.PATCH-alpha.N.
2. Preserve unrelated changes. Update only the four version files, version-specific
   notes and changelog when explicitly requested. Do not stage all changed files.
3. Run release:check, test:release, complete quality gates and relevant native tests.
4. Use a reviewed PR into main; only push/create/merge it when the user requested it.
   Do not invent author/co-author identities or rewrite upstream contributions.
5. Only when authorized, tag the verified main SHA and push that exact tag to origin
   qingtian-4/TaskPulse. The workflow produces a draft pre-release, not a stable release.
6. Check actual CI/assets/installer evidence. Record missing clean-machine,
   cross-version upgrade, real approval, focus and latency acceptance honestly.
7. Publishing the draft is a separate manual decision after the acceptance checklist.
   Never treat a successful build or autogenerated source archive as an installer.
