## 本次：任务优先面板与可配置来源

已落地来源实例注册表、独立管理窗口、项目允许/排除范围、会话目录和任务优先面板。Windows/WSL DeepSeek、每个远端 Codex/tmux 独立启停；首次确认前不采集，旧配置保留原项目范围并在首次保存时备份，设置保存热更新。不因数量限制丢掉运行/未查看任务，误隐藏可撤销或从目录重新关注。

普通本轮结束与真实授权/问题阻塞分开展示；隐藏只针对非运行的当前 turn，新执行重新进入，永久忽略需手动恢复。通知按任务逐条发送，去重跨重启保留。新 turn 在两次轮询间完成也能进入关注列表；原生标题重命名不改变身份、不重复通知。数据丢失或缩小范围不被当作成功。

真机发现并修复：自身状态文件触发重复采集的反馈循环、同步创建管理窗口的 Windows WebView2 死锁、CSP 拦截本机 IPC、停用后重新启用 Codex 的刷新通道失效、旧远端记录借用“本机”来源标签，以及 Codex Guardian 内部审查混入用户任务。Guardian 按明确原生来源标记过滤，而不是按标题。

本次自动化：256 项 Rust 测试通过、4 项 opt-in 默认跳过；fmt/clippy（deny warnings）、Svelte check（0 错误/警告）、前端构建通过。另有 3 项 UI 模型测试和 5 项 Python 元数据兼容测试。模拟 IPC UI 冒烟用 28 条任务验证滚动、布局、已查看及管理交互；它不等同于实际原生测试。

真实数据：只读 Windows DeepSeek 快照通过，读取到原生标题/项目/状态；真实 SSH 快照通过，强制断言 Server1 的 YOLO-RDD /“梳理 YOLO-RDD 项目流程”。Server3 连接正常，但本次没有新鲜 HyperMem 活跃快照，不声称验证了其完整运行树。正常权限 15 秒采样中 Codex/Hermes/Windows DSH/WSL DSH 分别返回 13/15/15/8 次，账号额度有两次新的成功读取时间；这不是端到端任务时延测量。

实际 Windows 托盘已验证内置前端、440×720 布局、原生管理窗口、保存与停用/恢复来源、扫描降级不能绕过停用、恢复后会话 ID 和监控范围不变。真实通知调用被系统 API 接受。可复现脚本见 `scripts/native-ui-smoke.ts`；截图与结果在本机忽略提交的 target 目录。还没有用户点击实际横幅的验收证据，也没有多轮真实任务的 P95 数据，不能宣布稳定版。

## 要解决的问题

用户同时运行多个 coding agent，却需要切换多个对话才能判断谁仍在工作、谁已结束、谁需要输入。TaskPulse 用一个托盘面板呈现真实任务名称、项目、状态和当前活动；结束/输入门控/失败后通知一次，并保留未查看任务，减少反复切换对话对注意力的打断。

当前提供的是独立桌面伴随应用。通用 IDE 插件、完整计划步骤和完成百分比尚未实现。

## 相对上游的扩展

[AgentTray](https://github.com/sprklai/agenttray) 已支持多 CLI 会话、hooks、CPU 扫描、系统通知和终端跳转。这些是复用基础，不是 TaskPulse 新发明的能力。

TaskPulse 增加原生会话采集（Codex/Hermes/DeepSeek）、项目与服务器分组、远程 Codex/tmux、tp-run 精确退出结果、动态关注生命周期、监控范围过滤、持久化未查看/固定状态及采集健康提示。身份使用稳定 session/thread ID，重命名不创建新任务。

## 本轮审查发现与处理

| 问题 | 处理 |
|---|---|
| Codex app-server 查询与本地扫描串行阻塞全部数据源 | 元数据后台查询；每个本地采集器独立线程，结果由主循环及时发布 |
| 仅监听 hook 目录，原生会话变化依赖慢轮询 | 增加 Codex rollout/SQLite WAL 和 Hermes 数据库目录监听，1 秒轮询兜底 |
| DSH 6 秒节流叠加主扫描延迟 | 独立 2 秒采集周期，结果不等扫描；WSL 单次命令 15 秒超时 |
| DSH 原生标题/状态缓存读取失败仍报告健康 | 显示降级并标记旧状态，避免把日志回退当成原生实时状态 |
| 文件监听失败导致主循环退出 | 记录错误并继续轮询 |
| 未返回的采集器没有可见状态 | 初次采集提示；30 秒未返回则降级，保留且标记上次快照 |
| 通知插件吞掉底层异步发送失败 | 直接使用相同的原生通知库取得结果；测试按钮/CLI 返回错误 |
| Codex 结束后的 token_count 把状态改回运行 | 结束状态保持，直到新的执行信号；增加回归测试 |
| 运行时长使用最近活动时间，反复归零 | 改用真实 turn 开始时间；无法获得时不显示时长 |
| 看执行指令要点开每条详情 | 每条任务直接显示活动摘要和状态，总览显示运行/等输入/失败/待查看数量 |
| 新用户默认连接个人示例服务器、README 克隆上游 | 新配置远程列表为空；正确克隆 TaskPulse；修正产品名与个人环境说明 |

## 实际验证（本机，非演示数据）

两次 10 秒采样均为 Codex 10 次、Hermes 10 次、DeepSeek 5 次；首次结果约 Codex 0.8–1.1 秒、Hermes 0.1 秒、DeepSeek 0.4–0.6 秒。最终一次查询耗时分别 167 / 4 / 316 ms。识别到项目 agenttray 的“评审 AgentTray 监控界面”为 RUNNING。Hermes/DSH 此时没有范围内活跃任务，不能据此声称观察了其实际结束/重命名。

进程扫描在该次 10 秒窗口内未返回；它的独立线程保证不会再拖住上述数据源。采集周期不是端到端延迟承诺，文件写入、负载和版本变化仍影响结果。

真实 SSH 冒烟：配置中的 Server3 可达，快照解析通过；本次未返回范围内任务，所以未验证 HyperMem 活跃树或真实远端完成通知。

新版 `--test-notification` 已调用原生通知 API，系统接受请求。API 接受不等于用户肉眼看到横幅：Windows 通知权限/请勿打扰仍须在桌面验收。

回归覆盖：真实临时 rollout 文件→后台 worker→Store→Transition→Attention，验证开始/完成、通知事件一次、重命名不重复、标记已查看移出、新 turn 重新加入；另外覆盖慢采集器隔离与刷新唤醒。自动化测试通过不替代真机交互验收。

最终自动化结果：223 项 Rust 测试通过、2 项 opt-in 活体测试默认跳过；fmt/clippy、Svelte check（0 错误/警告）、前端构建通过。另行执行了真实远端冒烟。桌面程序已用内置构建前端及 `--show` 入口启动，无需依赖 Vite 开发服务器；已确认进程运行且响应，启动日志未发现窗口创建错误。尚未通过工具核验窗口可见性、外观或通知横幅。

## 开源发布前仍需完成

### 2026-10-09 后续：额度刷新与 Server1 接入

排查确认：原配置中 Server1 被禁用；实际 IDE 连接别名与配置别名使用不同 SSH 用户，且 YOLO-RDD 未加入项目范围。本机配置已改为实际账号与项目，保留 Server3 原范围；不将这些个人别名硬编码到产品默认配置。

额度改为独立账号快照，明确显示本地账号来源、成功读取时间、刷新中/失败/过期状态。后台约 10 秒读取原生额度接口，手动刷新会唤醒；即使会话历史为空或标题查询失败，额度也可独立更新。删除日志额度跨任务传播，避免远端其他账号和旧会话污染结果。API 失败不会更新成功时间，超过 60 秒或最近一次查询失败时标为待更新。

远端元数据改为只读、动态 schema 查询，兼容缺少 name/is_pinned/archived 的版本，容忍索引中的半写入行；手动名称优先。无标题的活跃会话使用稳定 ID 降级显示，不再直接丢弃。取消最近 rollout 的固定 20 条上限，保留文件头提供稳定会话 ID/项目；远程轮询改为起始时间间隔，不额外叠加 SSH 耗时。

真实验证：Server1 的“梳理 YOLO-RDD 项目流程”被采集为 YOLO-RDD / WAITING_INPUT；原生日志确有 task_complete，且目标会话通过当前监控范围过滤。25 秒额度采样取得三次成功响应，约在首次、第 5 秒手动唤醒及随后 10 秒轮询；剩余量约 82% / 23%，成功读取时间确实变化，而非 UI 重绘旧值。比例随实际使用变化，不要求等于较早截图的 93% / 25%。

自动化：228 项 Rust 测试通过、2 项 opt-in 默认跳过；5 项 Python 元数据兼容测试通过；fmt/clippy、Svelte check（0 错误/警告）、前端构建通过。另行运行真实 SSH 测试并强制断言项目与原生标题存在。新版本项目托盘已重建、重启；进程响应正常。当前环境不能可靠核验窗口截图，不把后台验证当成外观验收。

限制仍在：这是轮询，不是服务端实时推送；远程账号额度尚未独立查询。新接入项目时已经结束的历史会话不自动回灌；新 turn 会进入关注列表。远程采集仍按同批主机等待结果，大日志仍非增量传输；多主机持续任务的端到端 P95 和真实结束横幅还需活体验收。

### 2026-10-09 后续：DeepSeek Harness 桌面版

本机已安装并运行 DeepSeek Harness Desktop。旧采集器只访问 WSL 的旧日志名及聚合缓存，漏掉 Windows `~/.dsh` 下的 v4 日志与分片投影。已增加独立桌面 worker，支持 v4/旧日志、投影 v7 `version/record` 包装及旧聚合缓存，保留 WSL 通道；原生目录只读，不接触凭据、桌面私有 API 或安装文件。

本机真机冒烟读取 4 条会话元数据，输出 2 条时间范围内会话。原生标题“电商客服Agent开源项目调研”、项目 E-commerce Agent 与 WAITING_INPUT 均被正确识别。10 秒正常权限诊断中桌面采集返回 10 次、首次约 609 ms、最后一次约 6 ms；WSL 同时返回 5 次且健康。另一受限环境诊断中 WSL 访问被拒绝，桌面仍正常返回 10 次，验证了采集隔离。

新增回归：v4 开始/命令/完成、只改变标题缓存的重命名、旧 projection 不得复活已结束任务、半写入缓存降级且保留原生标题、旧/v4 日志并存去重、step 间仍有 open turn 时保持运行、完成通知事件一次、隐藏后新 turn 再出现、历史空闲会话不回灌。238 项 Rust 测试通过，4 项 opt-in 默认跳过；真实 desktop snapshot 另行执行通过。fmt/clippy、Svelte check（0 错误/警告）、前端构建通过。

以上是真实存储读取和自动化生命周期验证，尚未主动提交桌面 Agent 新任务进行开始/结束/通知横幅的端到端活体验收。1 秒是采集周期，不是端到端实时承诺；仍需用户下一轮任务验证真实 GUI/横幅及未来格式兼容性。

1. 活体验收：分别启动 Codex/Hermes/DSH 的两条任务，实测开始、完成、门控、重命名、隐藏/恢复和重启；记录源事件到 UI/通知的 P50/P95 延迟。建议目标本地 P95 2 秒以内；这是验收目标，不是当前承诺。
