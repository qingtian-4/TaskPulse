# TaskPulse 路线图与需求范围

2026-10-27 整理。以下是产品方向，不是已交付功能或发布日期承诺。

## 产品目标

让用户无需反复切换 Agent 窗口，就能知道哪些任务在运行、需要回答或批准、失败，或已有结果待查看。桌面端负责采集与状态判断，计划中的手机 App 让用户离开电脑后也能查看和收到提醒。

## 已有基础

- Windows 托盘、关注面板、消息中心、来源管理和独立弹窗。
- 多来源聚合、稳定任务身份、未查看与固定记录、事件通知去重。
- 部分本机/WSL/SSH 来源；标准事件、声明式映射与本机 MCP 主动上报接入口。

具体支持等级以[兼容性矩阵](AGENT_COMPATIBILITY.md)为准。现有桌面候选包不包含手机 App、跨设备同步或移动推送服务。

## 计划需求

| 方向 | 用户体验 | 初步验收目标 |
|---|---|---|
| 手机任务概览 | 查看已配对电脑上的 Agent、项目、任务及最近状态 | 区分运行/待处理/结果/失联；注明来源电脑和更新时间 |
| 手机通知 | 收到待回答、待批准、失败与本轮结束提醒 | 复用明确生命周期事件；去重、延迟和断线补发行为可验证 |
| 跨设备状态 | 查看同一任务的详情与阅读记录 | 消息已读、结果已查看、请求已解决独立同步；旧消息不能解除新请求 |
| 设备连接 | 配对、撤销连接，查看电脑是否在线 | 授权范围明确，离线不冒充任务完成；同步字段和凭据管理有明确设计 |
| 更多 Coding Agent | 在来源管理中配置更多宿主 | 每款记录支持版本、事件能力与真实样本；检测到安装不等于完整支持 |
| 桌面可靠性 | 安装升级、混合 DPI、长时间运行 | 保留配置和未查看状态；来源故障恢复不重复提醒 |

## 建议阶段

1. **桌面基础与接入完善**：继续完善现有适配器和来源健康，优先补齐 Kimi/TRAE/ZCode 的真实宿主验证，调研 WorkBuddy 等未接入宿主。
2. **手机只读原型**：从已配对电脑读取任务列表和详情，显示更新时间与失联状态。Android/iOS 的首发顺序、客户端技术栈和连接方式待确定。
3. **移动推送与同步**：补齐后台/锁屏通知、重连补发、去重、已读与结果查看同步，并进行真机验证。连接/推送服务方案另行设计。

手机端第一阶段只查看和提醒，批准或回答仍在原 Agent 中完成。若未来增加手机远程回答或批准，需要单独设计请求身份、权限、确认与过期处理，不能把“点开通知”作为批准。
