# TaskPulse 任务面板与来源管理

标准面板 412×620 逻辑像素，0–1 个任务初次打开时为 412×400；新一轮执行会撤回该会话旧的结束弹窗。
明确授权/提问/额度耗尽标为“需处理”，思考或模型等待仍为运行中，普通结束进入待查看。
额度提醒要求来源提供明确、非自动重试的额度错误；普通限流、服务繁忙与本机账号百分比不替代其他环境的任务证据。
重启恢复的关注 / recent 快照先标为待验证，保留未读和固定状态；来源新鲜观察到达前不重放提醒，也不推进通知基线。
各来源的能力与验证范围见[兼容矩阵](AGENT_COMPATIBILITY.md)。

通用 Agent 来源提供本机标准事件 / MCP、受限描述导入、能力分级、配置预览/明确确认和自有 Hook 撤销，见[指南](AGENT_INTEGRATION_GUIDE.md)。MCP 由宿主主动上报，连接本身不会自动发现任务；测试连接也不创建任务。Windows Hook recipe 有界且不执行导入描述中的代码。宿主仍按[兼容矩阵](AGENT_COMPATIBILITY.md)标为部分/待实机验收，不能将“已配置”展示为“全面支持”。

目标：多个 coding agent 同时执行时，不必逐个打开对话查进展。扫一眼关注面板，就知道谁正在做什么、谁需要处理、哪些结果还没看；无需把面板一直置顶，任务事件会分别通知。

## 使用方式

### Alpha.7 界面操作

- 搜索同时匹配任务标题、项目、Agent、位置与当前活动；多个关键词取交集。`/` 聚焦搜索，输入框内 `Esc` 清空关键词。
- 筛选区的“仅未查看”与来源、项目、状态筛选可组合，包含运行中未查看任务，不修改未读状态；不同于顶部仅统计结果的“待查看”。上方全局计数一键清除限制，避免新项目被旧筛选遮住。
- 同组明确待批准 / 待回答任务优先，思考、工具执行和模型等待仍为进行中。标题最多两行，完整标题见悬停与详情；列表不限制任务总数，支持滚动和组内方向键导航。
- 选择任务只打开详情；只有“已查看”更新未读状态。详情前置当前活动，采集时间与状态依据可展开。
- 来源页按“选择 Agent → 查看能力与配置范围 → 保存并测试 → 等待真实任务事件”使用。安装发现、已保存、读取正常、测试提醒投递和宿主生命周期验收是不同证据，互不替代。
- “测试读取来源”等待所选来源本次采集，不借用其他来源或旧成功；“发送测试提醒”仅测试通知通道，不创建任务。逐项能力标明受限 / 不支持项和实机版本。Adapter ID、Manifest、Hook 差异、排除与诊断在高级区域；写 Hook 仍需预览和明确同意。

当前 Alpha.7 没有公开安装包；从源码启动与依赖准备见 [安装指南](INSTALL.md)。GitHub 首页只保留产品概览，原 README 的状态语义、隐私、Claude/服务器接入细节以本指南和安装指南为准。

1. 托盘点击或 `Ctrl+Shift+A` 打开面板，齿轮打开独立管理窗口。
2. 在“监控来源”启用需要的实例。Windows DeepSeek、WSL DeepSeek、每个 SSH 服务器分别配置，不混为同一来源。
3. 默认自动关注该来源所有项目的新执行；也可设置项目名称/完整路径的允许列表、排除项目、tmux session/pane。完整 Linux 路径区分大小写，Windows 路径不区分；`@unassociated` 表示未关联项目。
4. 已完成首次设置的来源启用开关即时应用；新增来源、项目范围及其他编辑点击“保存并生效”。关闭管理页时提示未保存编辑；其他窗口更新配置时禁止用旧草稿覆盖。新增范围不会批量导入空闲历史；停用不意味着任务完成，扫描降级不能绕过停用或范围限制。
5. 找回误隐藏的会话，可使用面板“撤销”，或在“已发现会话”搜索并“加入关注”。目录有分页；主关注列表没有数量上限。未启用的来源不会持续发现会话。

新安装不采集直到确认首次设置。已有配置按旧范围迁移，不擅自扩大项目范围。只在用户保存时改写旧配置，并保存一次迁移备份；无效配置保持原文件，暂停来源并展示错误。

## 面板组织

顶部三个主指标为“进行中、待处理、待查看”。待处理是进行中的子集，计数不相加；仅来源新鲜、明确的人机请求进入待处理，工具返回/模型等待/普通本轮结束不进入。来源失败或成功记录过期时，旧运行/请求移入待确认显示，不伪装为实时任务。“全部”保留为次级入口；只有异常时显示“来源待更新”或“上次运行，采集待确认”。搜索、固定与较早关注保留原数据。

- 进行中：真实运行与明确授权/问题阻塞，行内状态保留实际含义。思考和模型等待仍为运行，没有总步骤时不编造百分比。
- 结果待查看：本轮结束、成功或失败但尚未查看的结果；普通 tmux 推断返回 shell 显示退出码未知。
- 状态待更新：失联/过期/未知的观测，不是业务失败，也不能产生完成通知。
- 固定与已查看：仍需保留的非运行记录。

默认任务优先；可切换按项目分组，并按来源、项目、位置筛选。项目身份使用来源实例和完整路径，不把不同目录中同名项目合并。标准面板 412×620 逻辑像素；0–1 个近期任务初次打开时高 400，展开详情、筛选、额度或消息中心及任务增多时升到 620。同次打开期间只增高不自动缩小，固定窗口不随刷新收缩；重新打开未固定窗口时重新选择高度。判断使用原始任务数量，不随 stale、搜索或筛选变化跳动。

窗口按所在屏幕的实际工作区、DPI 和 8px 边缘留白限制宽高与位置；小屏优先保留滚动。前端填满原生客户区，不再通过 ResizeObserver 把受当前窗口限制的高度反馈回窗口。任务标题 14px、活动 12px、上下文与状态 11px，长标题/活动最多两行。来源健康与本地额度合为一行，额度和诊断仍可展开。已发布的 Alpha.7 展示截图属于此前布局；本轮开发版截图由隔离原生验收输出，不冒充已发布安装器界面。

默认“近期活动”窗口为 7 天，可在管理页“通知与显示”选择 3/7/14/30 天，或全部关注（配置 `dashboard.recent_days=0`）。按实际执行变化计算，采集刷新、标题/项目重命名不延长时间。正在运行的任务不受时间限制；TaskPulse 中明确手动固定的任务始终显示。其他长期未执行的关注移入“较早关注”，**保留状态、未读和旧固定标记，不删除记录，也不自动视为已查看**。包括旧的失败/等待项，因此不会继续占据近期面板。

旧版本无法区分固定标记来自采集器、历史迁移还是手动设置；升级保留这些标记，但长期不活跃的旧固定也归档。在较早关注中“固定到近期面板”可明确恢复常驻，“重新加入”则重新给予一个近期窗口。旧项目新 turn 开始时自动回到近期面板，长期“不再监控”仍须手动恢复。升级到 attention v3 前备份 `attention.json.pre-recency.bak`，不要直接用旧二进制覆盖新状态；回退旧版本时应先停止托盘、备份新文件，再恢复迁移备份。

进行中、待查看、待更新的统计和分组共用语义分类；待批准、待回答、失败结果有独立筛选，来源异常进入来源管理。全局计数点击清除项目/来源/位置旧筛选。历史远程记录按服务器与来源类型解析，不错误归到本机。

本地 Codex 额度折叠在底部，是账号数据，不是任务进度，也不代表远程账号额度。显示成功读取时间、5h/7 天重置时间、更新中和失败/过期提示。

Codex · WSL 是独立的本机来源，按发行版启用并单独设置项目范围；Windows Codex 来源不隐式包含 WSL。发现已运行的发行版只提供候选，用户保存后才采集。复用原生日志解析和关注规则，不批量导入历史，不将 Windows 账号额度分配给 WSL 任务。详见 [WSL 接入与验证](WSL_CODEX.md)。

## 状态与动作

普通 turn 完成仍使用协议 `waiting_input`，但 `waiting_reason=turn_ended` 显示“本轮结束”，归到结果。只有原生结构化提问/授权或已验证的运行时阻塞信号才显示“需要确认/授权”；不根据回复里是否出现问号推断。

执行阶段 `phase` 与任务生命周期分离：`thinking`（明确思考事件）、`tool`（未返回的工具调用）、`responding`（生成回复）、`awaiting_model`（工具已返回/等待模型响应）都属于 `running`。Codex/Claude 按 call ID 追踪工具，收到对应 output/result 后清除当前指令；并行工具只结束匹配的一项。不展示思考正文。没有阶段事件时显示“来源未提供执行阶段”，不编造思考状态。

低 CPU、工具空档、静默日志、文件消失都不是 Agent 完成证据。扫描结果不能覆盖结构化会话/Hook 的生命周期；失去观测保留状态并标记待更新，不发完成弹窗。同一个稳定 turn 的状态抖动也不重置提醒去重。仅明确返回 shell 且有结束快照的普通 tmux 工作负载保留推断结束提醒；Agent 会话不使用这种推断。原生适配器已合并 Hook/日志后，新鲜的同会话后续观测可以推进状态，不被上一轮较强的 Hook 置信度永久锁住。

attention v4 升级前备份 `attention.json.pre-lifecycle.bak`（更旧的 v1/v2 仍用 pre-recency 备份）。v3 误导入的 Claude 历史错误，满足“没有手动关注/固定、原生未读证据缺失、错误时间远早于加入和执行记录时间”时保守移至较早关注，保留未读/固定标记和真实失败状态，不标记成功或已查看。可手动重新加入，新 turn 自动回到近期。首次启用来源不将无未读证据的历史失败/授权项导入主列表；真实新执行仍全部关注。

| 动作 | 行为 |
|---|---|
| 已查看 | 清未读；非运行、非真正阻塞、未固定时移出。运行中的任务结束后再次未读 |
| 固定 | 当前会话持续显示，跨重启保留；TaskPulse 手动取消固定优先于采集器的原生固定 |
| 隐藏本轮 | 非运行任务隐藏，新 turn 自动重新出现；运行任务不能隐藏 |
| 不再监控 | 忽略该会话，后续 turn 也不加入，直到在目录中恢复 |
| 加入关注 | 手动找回已发现的会话，不补发历史完成通知 |
| 聚焦运行窗口 | 仅有聚焦能力时显示；不宣称已打开精确会话，不自动确认已查看 |
| 复制任务信息 | 复制真实标题、项目/来源、路径和稳定会话 ID，以便在原生 Agent 中查找 |

身份始终用稳定 session/thread ID。完整原生标题保留；界面长标题省略，鼠标提示可看全文。重命名不会重置状态、另建任务或重复通知。

本地 Codex 的 Guardian 内部审查会话按原生 `source.subagent.other=guardian` 标记排除，不按标题排除；普通用户即使将任务命名为“Guardian review”，也不受影响。其他编码子任务不会因此一并被过滤。

## 提醒与数据可靠性

默认使用 TaskPulse 独立任务提醒窗，而不只依赖 Windows 系统横幅。任务本轮结束、成功、失败、需要授权/确认时，在屏幕工作区右下角显示原生标题与项目/来源；窗口不激活、不抢当前编辑焦点，也不要求主面板一直打开。普通结果显示 15 秒，鼠标悬停暂停收起；已确认的授权请求与结构化提问提醒没有自动关闭计时。关闭或“稍后处理”仅收起提醒，不标记任务已查看；“查看详情”打开 TaskPulse 的当前任务详情，仍须用户确认已查看。待展示提醒可通过“下一条”切换，不丢弃当前阻塞提醒；每次重展示使用新 presentation ID，迟到计时回调不能关闭它。新鲜来源观察确认对应请求已处理/返回后，自动移除该阻塞提醒；缺失、过期或断连不算请求已处理。

### Codex 授权证据边界

工具调用提交、提权参数与迟迟未返回的结果都不能证明命令正在等批准：它可能已自动批准并运行，也可能在等待工具响应。因此 Windows / WSL / SSH 共享解析器不再根据命令耗时推测审批，不生成“授权状态待确认”提醒，也不把这些 RUNNING 任务放入“需处理”。真实指令与思考/模型等待阶段继续展示；工具结果按匹配 call ID 清除活动，本轮结束仍必须由明确生命周期事件确认。

来源明确记录审批请求与 resolved 事件时，才设置 `WAITING_INPUT / approval`，按稳定 request ID 跟踪和解除。确认提醒按 turn + request ID 去重，跨刷新、短暂状态抖动和应用重启保留；后续真正完成仍独立提醒。当前桌面端普通 rollout 没有完整的待审批事件，所以这类来源可能漏掉授权提醒，不能宣称精确审批检测，不能用另起的 app-server 冒充原实例状态。不自动安装 Hook、修改审批策略或响应任何审批。

升级兼容旧关注记录中的 `approval_hint`（忽略该字段）和 `awaiting_tool` 阶段（只显示等待工具响应）。保留会话身份、未读、固定与通知去重；旧的投递记录仅作历史证据保留，不再产生检查提醒。临时弹窗队列不跨重启补弹。

Claude 的显式 Hook 接入现在写入按会话加锁、递增 sequence 的 JSONL 事件日志，latest JSON 仅作兼容检查点。官方 [PermissionRequest 输入](https://code.claude.com/docs/en/hooks#permissionrequest-input) 不包含 `tool_use_id`；只在 tool name/input 指纹唯一匹配 preceding PreToolUse 时关联 call ID。多个批准分别保留与通知；Notification 复用未解决请求，匹配的 PostToolUse／PostToolUseFailure 只解除该请求，不代表整轮完成。无可靠关联时保持不确定的显式批准，直到明确结束／新 turn；不猜测批准结果。仅 busy/idle 心跳或 thinking 不能解除批准或通知完成。Hook 安装仍须用户显式确认；不会自动改现有 Hook／statusLine／代理。

### 投递证据

管理窗口“通知与显示”提供投递记录，只读刷新。`~/.taskpulse/notification-log.json` 原子保存最近 500 条事件：已识别、关闭/范围抑制、已入队、原生窗口可见、渲染器确认、用户收起、计时收起、打开详情、请求返回/处理以及投递失败。系统渠道仅记录 API 接受/失败，不冒充横幅显示。“已渲染”不证明用户阅读；与 `notifications.json` 的生命周期去重职责独立。记录不包含 Agent 命令、提示词或凭据，升级前的投递不能追溯补录；审计文件不进入监控来源，也不触发采集循环。

提醒窗采用与主面板一致的深色窄条消息卡片：320 × 132px、深灰底色、低饱和 TaskPulse 图标、细边框和圆角，不使用白色系统外框。上方为来源/服务器/项目，中间突出原生任务名称（最多两行，悬停可看完整名称），下方为结果摘要与轻量操作按钮。保留消息卡片的信息层级，但不沿用白底样式或大块头像。通知元数据按独立字段传输，不能拆分含 ` · ` 的消息字符串来猜任务名；点击消息主体也可查看详情。

每个任务各自提醒，不合并：短暂弹窗队列最多 128 条，满时优先移除非当前的普通提醒；所有阻塞已满时新提示保留到面板回查，不改变未读和任务状态。显示剩余提醒数量；确认阻塞在后续提醒等待时约 15 秒轮转，悬停暂停，轮转不解除请求。同一 turn/事件由状态机去重，刷新和重命名不重复弹出；旧 ID 的回调不关闭下一条。

右上角铃铛是消息中心，角标只表示未阅读的消息。打开后，原生面板可见且消息行进入列表视口时确认该条已读；未滚动到的消息保留未读，也可“全部标为已读”（只确认点击时的消息批次）。消息中心保持打开时新消息继续进入相同阅读规则，隐藏窗口不会确认阅读。阅读消息不等于查看任务结果，更不代表批准或解除请求；关闭提醒窗也不改变这三种状态。

`messages.json` 独立保存最近 200 条、最多 256 KiB 的消息类别、哈希身份、时间与阅读标记，使用原子替换；坏文件/未知版本保留原文件并禁止覆盖。标题与项目从当前范围内的任务临时关联，不额外保存 prompt、参数或回复。只接收 Transition 已去重的明确请求/额度/完成/失败/中断事件，来源故障与低可信推断结束不进入消息中心。标准事件的显式结束与其 self-reported 来源置信度分别保留，不伪称官方 Hook。总提醒开关和来源范围继续适用。原有 delivery log 的 rendered 不证明已读，因此不能替代阅读状态；Task Unread 也不能复用，因为一项任务可以有多个已读但未解决的请求。

消息中心的折叠区继续从 Attention 恢复“当前与待核对请求”，包含较早/隐藏但未永久忽略的请求，**不补造历史未读消息**。只有新鲜、来源明确且仍在范围内的请求可手动重开；过期/未知/内部/范围外不重开。重开校验匹配 turn/request，使用新展示 ID，不修改消息已读、任务已查看或生命周期去重。请求未解决时，即使消息已读，“待处理”仍保留；来源失联则保留待核对入口。短暂队列不跨重启重播。

管理页“通知与显示”可选择独立弹窗（默认）、系统通知或两者（`dashboard.notification_mode=popup/system/both`），总提醒开关对所有渠道生效，声音默认关闭。停用提醒立即清空/隐藏提醒窗；停用来源或忽略任务移除其待展示提醒。系统通知仍可能被系统勿扰/横幅权限隐藏；独立弹窗是应用窗口，不依赖这些设置，不改写操作系统通知偏好。测试按钮展示明确标注的测试提醒，绝不添加虚假关注任务。创建/发送错误显示在管理页。

通知状态跨重启保存。新 turn 或新的结构化问题 ID 可以再次提醒；重命名不提醒。任务在两次采样间开始并结束，也可以根据新 turn 和关注基线进入列表并通知。历史基线和手动加入不触发历史通知。

原生数据丢失、SSH/读取失败、缩小范围不能冒充完成。已有可信生命周期保留，但标记“状态待更新”；恢复后继续同步。Windows 和 WSL 各自有权威分区，一方空结果不能删除另一方任务。

刷新按钮等待每个启用来源在请求时间之后的真实采集尝试返回，而不是固定 1.2 秒结束动画。显示已返回/总来源数、失败来源；30 秒仍未返回则明确超时，旧状态保留。各任务标出对应来源最后成功采集时间（详情另显示最后任务活动时间），不使用其他来源较新的成功时间伪装全局实时。没有具体活动信息时明确说明，不显示虚构的“正在分析”。

## 验证与限制

运行 `scripts/verify.ps1 -Frontend` 和 `bun run test:ui-model`。UI 冒烟脚本 `scripts/ui-smoke.ts` 使用隔离 Edge CDP 与模拟 IPC，输出截图和检查结果到 `src-tauri/target/ui-smoke/`；它验证布局和交互，不代替真实 Tauri/Agent 活体验收。

`scripts/native-ui-smoke.ts` 则连接真实 Windows 托盘，检查原生管理窗口、配置热更新和来源停用/恢复，并发送一次真实测试通知。它会保存 TaskPulse 配置（保留范围并在 finally 恢复），不是只读测试；操作步骤和证据边界见 [开发说明](DEVELOPMENT.md)。验证后关闭临时调试端口，勿在日常运行中保留。

`scripts/native-notice-smoke.ts` 专门验证真正的完成/失败/已确认授权提醒窗口、焦点保持、顺序队列、悬停暂停、普通结果 15 秒收起、阻塞提醒超过 15 秒不消失及后台拒绝计时关闭、切换下一条、已移除的推测提醒不再可发送及投递记录。长命令、增量缓存、真实远端历史日志回放和旧持久记录兼容另有回归测试。它暂时选择静音弹窗并最终恢复配置，不修改 Agent 或关注记录。明确标注的测试事件能够验证通知呈现；真实 Agent 的新完成事件到弹窗的端到端延迟仍需独立测量，不以 API 接受请求作为横幅实际显示的证据。

Windows 锁屏时可显式设置 `TASKPULSE_SMOKE_LOCKED_DESKTOP=1` 运行弹窗渲染与队列检查；结果的 `focusPreserved` 为 `null`，并将编辑器焦点保持列入 `notVerified`，不算焦点验收通过。默认模式仍要求实际前台窗口聚焦并保持焦点。

本地周期约 1 秒、WSL 2 秒、远程默认 3 秒，均不是端到端时延保证。目标为来源事件可读后本地 P95 ≤2 秒、远程 P95 ≤6 秒，尚需多轮真实任务测量。暂不支持通用原生会话深链接，也不可靠获知所有 Agent 的原生阅读状态。远程快照仍有 24 小时的 rollout 发现窗口，已关注结果由本地持久记录保留；窗口外持续运行且没有日志更新的远程任务可能显示过期，不能承诺完整实时发现。大型日志增量化、逐服务器流式发布、跨平台 GUI/通知验收和发布安装包留待后续版本。
