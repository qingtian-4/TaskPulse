# TaskPulse 任务面板与来源管理

目标：多个 coding agent 同时执行时，不必逐个打开对话查进展。扫一眼关注面板，就知道谁正在做什么、谁需要处理、哪些结果还没看；无需把面板一直置顶，任务事件会分别通知。

## 使用方式

1. 托盘点击或 `Ctrl+Shift+A` 打开面板，齿轮打开独立管理窗口。
2. 在“监控来源”启用需要的实例。Windows DeepSeek、WSL DeepSeek、每个 SSH 服务器分别配置，不混为同一来源。
3. 默认自动关注该来源所有项目的新执行；也可设置项目名称/完整路径的允许列表、排除项目、tmux session/pane。完整 Linux 路径区分大小写，Windows 路径不区分；`@unassociated` 表示未关联项目。
4. 已完成首次设置的来源启用开关即时应用；新增来源、项目范围及其他编辑点击“保存并生效”。关闭管理页时提示未保存编辑；其他窗口更新配置时禁止用旧草稿覆盖。新增范围不会批量导入空闲历史；停用不意味着任务完成，扫描降级不能绕过停用或范围限制。
5. 找回误隐藏的会话，可使用面板“撤销”，或在“已发现会话”搜索并“加入关注”。目录有分页；主关注列表没有数量上限。未启用的来源不会持续发现会话。

新安装不采集直到确认首次设置。已有配置按旧范围迁移，不擅自扩大项目范围。只在用户保存时改写旧配置，并保存一次迁移备份；无效配置保持原文件，暂停来源并展示错误。

## 面板组织

- 需要处理：权威失败、明确授权/问题阻塞、数据过期需检查。
- 正在运行：真实进行中 turn、有效租约或运行进程。展示项目、来源实例和当前活动；没有可靠总步骤时不编造完成百分比。
- 结果待查看：本轮结束或已完成但尚未查看的结果。
- 固定的空闲任务：固定且已查看的非运行会话。

默认任务优先；可切换按项目分组，并按来源、项目、位置筛选。项目身份使用来源实例和完整路径，不把不同目录中同名项目合并。面板宽 440 逻辑像素，高度不超过 720 或当前屏幕可用高度的 80%，任务区域滚动，不截掉超限任务。

默认“近期活动”窗口为 7 天，可在管理页“通知与显示”选择 3/7/14/30 天，或全部关注（配置 `dashboard.recent_days=0`）。按实际执行变化计算，采集刷新、标题/项目重命名不延长时间。正在运行的任务不受时间限制；TaskPulse 中明确手动固定的任务始终显示。其他长期未执行的关注移入“较早关注”，**保留状态、未读和旧固定标记，不删除记录，也不自动视为已查看**。包括旧的失败/等待项，因此不会继续占据近期面板。

旧版本无法区分固定标记来自采集器、历史迁移还是手动设置；升级保留这些标记，但长期不活跃的旧固定也归档。在较早关注中“固定到近期面板”可明确恢复常驻，“重新加入”则重新给予一个近期窗口。旧项目新 turn 开始时自动回到近期面板，长期“不再监控”仍须手动恢复。升级到 attention v3 前备份 `attention.json.pre-recency.bak`，不要直接用旧二进制覆盖新状态；回退旧版本时应先停止托盘、备份新文件，再恢复迁移备份。

统计数字可直接筛选运行、需处理、待查看；高级筛选默认折叠。历史远程记录没有 `source_instance` 时按服务器与来源类型解析，而不是错误归到本机；采集过程中也补齐稳定来源实例。

本地 Codex 额度折叠在底部，是账号数据，不是任务进度，也不代表远程账号额度。显示成功读取时间、5h/7 天重置时间、更新中和失败/过期提示。

## 状态与动作

普通 turn 完成仍使用协议 `waiting_input`，但 `waiting_reason=turn_ended` 显示“本轮结束”，归到结果。只有原生结构化提问/授权或已验证的运行时阻塞信号才显示“需要确认/授权”；不根据回复里是否出现问号推断。

| 动作 | 行为 |
|---|---|
| 已查看 | 清未读；非运行、非真正阻塞、未固定时移出。运行中的任务结束后再次未读 |
| 固定 | 当前会话持续显示，跨重启保留；TaskPulse 手动取消固定优先于采集器的原生固定 |
| 隐藏本轮 | 非运行任务隐藏，新 turn 自动重新出现；运行任务不能隐藏 |
| 不再监控 | 忽略该会话，后续 turn 也不加入，直到在目录中恢复 |
| 加入关注 | 手动找回已发现的会话，不补发历史完成通知 |
| 聚焦运行窗口 | 仅有聚焦能力时显示；不宣称已打开精确会话，不自动确认已查看 |
| 复制任务信息 | 复制真实标题、项目/来源、路径和稳定会话 ID，以便在原生 Agent 中查找 |

身份始终用稳定 session/thread ID。完整原生标题保留；界面长标题省略，鼠标提示可看全文。重命名不会重置状态、另建任务或重复通知。

本地 Codex 的 Guardian 内部审查会话按原生 `source.subagent.other=guardian` 标记排除，不按标题排除；普通用户即使将任务命名为“Guardian review”，也不受影响。其他编码子任务不会因此一并被过滤。

## 提醒与数据可靠性

每个任务分别发送一次通知，不合并批量任务。本轮结束、阻塞、失败使用不同文案。Windows 通知点击定位当前会话详情；结果仍未读，直到用户确认。通知和声音分别设置，声音默认关闭。测试按钮可检查系统权限，通知发送错误显示在管理页。

通知状态跨重启保存。新 turn 或新的结构化问题 ID 可以再次提醒；重命名不提醒。任务在两次采样间开始并结束，也可以根据新 turn 和关注基线进入列表并通知。历史基线和手动加入不触发历史通知。

原生数据丢失、SSH/读取失败、缩小范围不能冒充完成。已有可信生命周期保留，但标记“状态待更新”；恢复后继续同步。Windows 和 WSL 各自有权威分区，一方空结果不能删除另一方任务。

刷新按钮等待每个启用来源在请求时间之后的真实采集尝试返回，而不是固定 1.2 秒结束动画。显示已返回/总来源数、失败来源；30 秒仍未返回则明确超时，旧状态保留。各任务标出对应来源最后成功采集时间（详情另显示最后任务活动时间），不使用其他来源较新的成功时间伪装全局实时。没有具体活动信息时明确说明，不显示虚构的“正在分析”。

## 验证与限制

运行 `scripts/verify.ps1 -Frontend` 和 `bun run test:ui-model`。UI 冒烟脚本 `scripts/ui-smoke.ts` 使用隔离 Edge CDP 与模拟 IPC，输出截图和检查结果到 `src-tauri/target/ui-smoke/`；它验证布局和交互，不代替真实 Tauri/Agent 活体验收。

`scripts/native-ui-smoke.ts` 则连接真实 Windows 托盘，检查原生管理窗口、配置热更新和来源停用/恢复，并发送一次真实测试通知。它会保存 TaskPulse 配置（保留范围并在 finally 恢复），不是只读测试；操作步骤和证据边界见 [开发说明](DEVELOPMENT.md)。验证后关闭临时调试端口，勿在日常运行中保留。

本地周期约 1 秒、WSL 2 秒、远程默认 3 秒，均不是端到端时延保证。目标为来源事件可读后本地 P95 ≤2 秒、远程 P95 ≤6 秒，尚需多轮真实任务测量。暂不支持通用原生会话深链接，也不可靠获知所有 Agent 的原生阅读状态。远程快照仍有 24 小时的 rollout 发现窗口，已关注结果由本地持久记录保留；窗口外持续运行且没有日志更新的远程任务可能显示过期，不能承诺完整实时发现。大型日志增量化、逐服务器流式发布、跨平台 GUI/通知验收和发布安装包留待后续版本。
